# Hunter application ownership — 2026-10-31

## Cause

Hunter resolved the correct window, PID and executable, but assigned an unrelated
installed program. Publisher-token substring matching accepted `Open` from
`OpenCode` in the process name `OpenUninstaller` with score 30. The dialog and
uninstall callback then used that incorrect `InstalledProgram`.

## Resolution

- Require executable-path evidence; names, publishers and window titles alone
  do not establish an installed application's ownership.
- Prefer an exact display-icon executable (120), then an exact uninstall
  executable (110), then the most specific containing install location (100).
- Reject relative locations and drive/share roots. Expand environment variables,
  normalize paths and compare without case, preserving directory boundaries.
- Leave equally strong distinct owners unmatched. Collapse identical metadata
  from the same HKCU uninstall key exposed through both registry views; prefer
  its 64-bit view consistently. Separate registrations remain distinct.
- Unmatched targets retain their process name and executable, using the existing
  file-scoped cleanup flow rather than another application's uninstall entry.

## Verification

- Before the fix, 15 of the initial 19 regression cases failed, including the
  OpenUninstaller/OpenCode reproduction.
- Final Release solution build with `-warnaserror`: zero warnings/errors.
- Final test suite: **193 passed**, including 26 new Hunter cases and the two
  existing Hunter cases.
- A local read-only probe scanned the real uninstall registry: the installed
  OpenCode executable correctly resolved to OpenCode despite duplicate HKCU
  views. The running development OpenUninstaller window resolved through its
  HWND/PID to OpenUninstaller, without an unrelated installed-program owner.
- The actual `HunterActionDialog` constructed from that live match displayed
  `OpenUninstaller`; its rendered content was visually checked. No uninstall,
  process termination or deletion action was invoked.

Build output: `artifacts/hunter-validation/bin/OpenUninstaller.App/release/`.
Local probe and rendering: `artifacts/hunter-probe/` (ignored build artifacts).
The already-running application keeps its previously loaded code until restarted.
