## Security hardening for the maintenance service and deletions

OpenUninstaller 1.0.10 closes privilege-escalation paths in the optional maintenance service,
makes every approved deletion resistant to junction swaps, and fixes several uninstall and
cleanup edge cases.

### Security

- **Service binaries under Program Files:** the LocalSystem maintenance service no longer runs from
  the per-user install folder, which any unelevated process could modify. `service install` copies
  it to `%ProgramFiles%\OpenUninstaller\Maintenance` and registers that copy; `service remove`
  deletes it again.
- **No redirected deletes as SYSTEM:** backup pruning and log/snapshot expiry inside
  `%ProgramData%\OpenUninstaller` delete through handles whose resolved path is verified, lock files
  are created inside pinned folders, and the service writes its own logs next to its binaries.
  A junction placed in the data folder can no longer point the service at system files.
- **Verified leftover deletion:** approved leftover files and folders use the same verified
  handles, so a junction swapped in after review cannot redirect an elevated deletion.
- **Earlier service installs are flagged:** `service status` and Settings warn when the service
  still runs from outside Program Files. Run `oucli service remove --yes` and
  `oucli service install --yes` from an elevated shell to move it.
- **Stricter path guard:** drive-relative (`C:folder`) and root-relative (`\folder`) paths are
  rejected, and protected roots such as `%TEMP%` are compared in their long form.

### Fixed

- Registry access denials (for example an HKLM leftover without elevation) fail that item instead
  of aborting the whole deletion or forced uninstall.
- Vendor uninstall arguments are passed verbatim, so commands such as
  `rundll32 "C:\Program Files\…\x.dll",Uninstall` work again.
- ClickOnce and other bare system commands (`rundll32.exe dfshim.dll,ShArpMaintain …`) resolve in
  the Windows system folders instead of being reported missing.
- Folders that contain read-only files are deleted completely.
- Restore results report their real duration; the service reports failures with a
  service-specific exit code.

Every deletion is still backed up first and can be restored from Backups.
